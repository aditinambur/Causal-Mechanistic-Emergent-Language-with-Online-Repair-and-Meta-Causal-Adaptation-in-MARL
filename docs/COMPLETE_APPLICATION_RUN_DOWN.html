Complete Run Down of the Multi-Agent Emergent Communication & Online Repair Platform

1. System Overview & Core Philosophy

1.1 The Research Problem

In Multi-Agent Reinforcement Learning (MARL), cooperative agents frequently learn emergent communication protocols—discrete or continuous message vectors exchanged to coordinate actions. However, real-world multi-agent deployments face distribution shifts, sensor drift, physical recalibrations, or partner swaps. When the environment shifts, learned communication protocols often become misaligned or counterproductive.

Standard RL approaches either: 1. Ignore communication: Retraining everything from scratch when task reward drops, which is computationally expensive and causes catastrophic forgetting. 2. Use naive reward-based triggers: Attempting retraining whenever reward falls, even if the failure is caused by physical dynamics rather than communication breakdown.

1.2 The Solution: The Meta-Causal Closed Loop

This platform implements a causal mechanistic framework that uses interventional diagnostics to monitor, detect, isolate, and repair broken emergent communication protocols in multi-agent systems.

3. How to Run on Terminal via Docker & View Results

Because this project relies on specific pinned dependencies (PyTorch 1.13.1, CUDA 11.6, Gym 0.19.0, NumPy < 2, Protobuf <= 3.20.3), running natively on Windows can lead to binary incompatibility issues. The entire stack is containerized using Docker and Docker Compose with NVIDIA GPU passthrough.

3.1 Starting the Docker Containers

From the repository root on your host machine:

# Build and start all services in detached mode
docker compose up --build -d

# Verify both containers are running healthy
docker compose ps

This launches two services: 1. backend: FastAPI API server running inside PyTorch CUDA container on port 8001 (mapped to internal 8000). 2. frontend: React + Vite UI running on port 5173.

3.2 Accessing the Interactive Interfaces

  • Frontend Dashboard: Open http://localhost:5173 in your browser.
  • Launch new training runs with custom hyper-parameters.

  • FastAPI Backend Swagger Docs: Open http://localhost:8001/docs.

4. The Complete Training Algorithm (MAPPO + Emergent Communication)

4.1 Multi-Agent Actor-Critic Setup

The platform operates on decentralized partially observable Markov decision processes (Dec-POMDP). In MPE simple_spread, $$L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left(r_t(\theta)\hat{A}_t, \, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right) \right]$$1 agents must coordinate to navigate and cover $$L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left(r_t(\theta)\hat{A}_t, \, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right) \right]$$2 landmarks while minimizing collisions.

  • Local Observation ($$L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left(r_t(\theta)\hat{A}_t, \, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right) \right]$$3): Agent velocity (2D), self-position (2D), relative landmark positions ($$L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left(r_t(\theta)\hat{A}_t, \, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right) \right]$$4), and relative other-agent positions ($$L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left(r_t(\theta)\hat{A}_t, \, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right) \right]$$5), plus communication state.
  • Centralized Critic State ($$L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left(r_t(\theta)\hat{A}_t, \, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right) \right]$$6): Concatenation of all agents' local observations.

4.3 PPO Policy Update

The policy parameters $$\text{comm\_effect} = \mathbb{E}_{\text{CRN}} \left[ R_{do(\text{normal})} - R_{do(\text{no\_messages})} \right]$$9 and value parameters $$\text{Value Sensitivity} = \mathbb{E}_{s \sim \pi} \left[ |V(s, \mathbf{c}) - V(s, \mathbf{0})| \right]$$0 are optimized using clipped surrogate objective: $$L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left(r_t(\theta)\hat{A}_t, \, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right) \right]$$ where $$\text{Value Sensitivity} = \mathbb{E}_{s \sim \pi} \left[ |V(s, \mathbf{c}) - V(s, \mathbf{0})| \right]$$1 is computed via Generalized Advantage Estimation (GAE).

5. The Causal Mechanistic Layer

Rather than assuming communication helps simply because agents transmit tokens, the Causal Mechanistic Layer directly measures the causal effect of communication on policy actions and expected values using Pearl's $$\text{Value Sensitivity} = \mathbb{E}_{s \sim \pi} \left[ |V(s, \mathbf{c}) - V(s, \mathbf{0})| \right]$$2-calculus.

5.1 Common Random Numbers (CRN) Harness

To eliminate confounding environmental variance between paired rollouts: - Every causal evaluation episode $$\text{Value Sensitivity} = \mathbb{E}_{s \sim \pi} \left[ |V(s, \mathbf{c}) - V(s, \mathbf{0})| \right]$$3 is executed under an identical deterministic initial state seed $$\text{Value Sensitivity} = \mathbb{E}_{s \sim \pi} \left[ |V(s, \mathbf{c}) - V(s, \mathbf{0})| \right]$$4. - Landmark positions, initial agent placements, and physical dynamics are bit-for-bit identical across all compared interventions.

5.3 Diagnostic Causal Fingerprint Metrics

  1. Causal Communication Benefit ($$\text{Policy KL} = \mathbb{E}_{s \sim \pi} \left[ D_{KL}(\pi(\cdot | s, \mathbf{c}) \parallel \pi(\cdot | s, \mathbf{0})) \right]$$3): $$\text{comm\_effect} = \mathbb{E}_{\text{CRN}} \left[ R_{do(\text{normal})} - R_{do(\text{no\_messages})} \right]$$ Directly measures the gain in task reward produced specifically by the communication channel.
  2. Causal Influence on Value ($$\text{Policy KL} = \mathbb{E}_{s \sim \pi} \left[ D_{KL}(\pi(\cdot | s, \mathbf{c}) \parallel \pi(\cdot | s, \mathbf{0})) \right]$$4): $$\text{Value Sensitivity} = \mathbb{E}_{s \sim \pi} \left[ |V(s, \mathbf{c}) - V(s, \mathbf{0})| \right]$$ Measures how much the centralized critic shifts its expected return prediction when messages are removed at state $$\text{Policy KL} = \mathbb{E}_{s \sim \pi} \left[ D_{KL}(\pi(\cdot | s, \mathbf{c}) \parallel \pi(\cdot | s, \mathbf{0})) \right]$$5.
  3. Causal Influence on Policy ($$\text{Policy KL} = \mathbb{E}_{s \sim \pi} \left[ D_{KL}(\pi(\cdot | s, \mathbf{c}) \parallel \pi(\cdot | s, \mathbf{0})) \right]$$6): $$\text{Policy KL} = \mathbb{E}_{s \sim \pi} \left[ D_{KL}(\pi(\cdot | s, \mathbf{c}) \parallel \pi(\cdot | s, \mathbf{0})) \right]$$ Measures the behavioral divergence in action probabilities caused by receiving peer messages.

Crucial Discovery: Under distribution shift, Policy KL often remains high while $$\text{Policy KL} = \mathbb{E}_{s \sim \pi} \left[ D_{KL}(\pi(\cdot | s, \mathbf{c}) \parallel \pi(\cdot | s, \mathbf{0})) \right]$$7 collapses to zero or becomes negative. This proves agents are still reacting to distorted messages, but the semantic meaning is corrupt.

6. The Online Repair Mechanism

6.1 Distribution Shift: Observation Mirroring

To systematically test protocol breakdown, the environment wraps observations with MirrorObsVecEnv. Under partner_full, the relative coordinates of partner agents are inverted ($$\text{Policy KL} = \mathbb{E}_{s \sim \pi} \left[ D_{KL}(\pi(\cdot | s, \mathbf{c}) \parallel \pi(\cdot | s, \mathbf{0})) \right]$$8). This leaves self-navigation intact but corrupts mutual belief about partner locations.

6.2 Dual-Gated Degradation Detection

The Phase 2 detector triggers repair only when both task performance and communication utility fail:

$$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$

Where: - $$\text{Policy KL} = \mathbb{E}_{s \sim \pi} \left[ D_{KL}(\pi(\cdot | s, \mathbf{c}) \parallel \pi(\cdot | s, \mathbf{0})) \right]$$9 (Threshold $$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$0) - $$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$1

6.3 Rule-Based Adaptive Controller

Instead of guessing which layers to fine-tune, the deterministic controller analyzes the fingerprint pattern:

  1. Reward Collapsed Badly ($$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$2 drop):
  2. Escalates immediately to parameter-efficient lora or full policy adaptation.
  3. Value Sensitivity Dropped Sharply ($$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$3):
  4. Starts minimally with embedding (re-learning token semantics while preserving policy trunk).
  5. Standard Communication Breakdown:
  6. Selects comm (token_embedding + message_head + attention_weight).

6.4 Bit-Exact Snapshot & Rollback Architecture

Before initiating PPO fine-tuning iterations in the broken environment, the system creates a deep-copy snapshot of: - Actor network weights (policy.actor.state_dict()) - Critic network weights (policy.critic.state_dict()) - Attention weights (policy.attention_weight) - Actor & Critic Adam optimizer momentum buffers (exp_avg, exp_avg_sq) - Value Normalizer running statistics (trainer.value_normalizer)

If a repair attempt is rejected, the snapshot is restored bit-for-bit, preventing optimizer momentum poisoning during subsequent escalation attempts.

6.5 Acceptance Gating & The Escalation Ladder

Normalized Recovery Metric:

$$\text{Recovery}(M) = \frac{M_{\text{repaired}} - M_{\text{degraded}}}{M_{\text{baseline}} - M_{\text{degraded}}}$$

A repair is accepted if and only if: $$\text{Recovery}(\text{Reward}) \ge 0.50 \quad \text{AND} \quad \text{Recovery}(\text{comm\_effect}) \ge 0.50$$

The Escalation Ladder:

  [ embedding ] ──rejected──> [ comm ] ──rejected──> [ lora ] ──rejected──> [ full ] ──rejected──> [ RESTORE & FAIL ]
        │                           │                       │                      │
     accepted                    accepted                accepted               accepted
        ▼                           ▼                       ▼                      ▼
  [ HELD-OUT VALIDATION CHECK ON INDEPENDENT SEEDS ] ──> [ PERSIST CHECKPOINT TO DISK ]

6.6 Held-Out Generalization Validation

When an attempt passes acceptance, the runner evaluates the repaired policy on a completely disjoint set of random seeds (CRN block). - If recovery is confirmed on held-out episodes: Emits HELD-OUT CONFIRMS and saves checkpoint_accepted_<target>/. - If it fails on held-out episodes: Rejects the fix, rolls back, and flags the run as an overfitted artifact.

7. The Parameter-Efficient LoRA (Low-Rank Adaptation) Method

7.1 Mathematical Formulation

When observation shifts are severe, updating only the communication embeddings (embedding / comm) is insufficient, but full actor fine-tuning (full) risks catastrophic forgetting on unbroken tasks.

The LoRA layer (LoRALinear in onpolicy/algorithms/utils/lora.py) wraps dense linear layers $$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$4 with a low-rank decomposition:

$$h = W_0 x + \Delta W x = W_0 x + \frac{\alpha}{r} (B \cdot A) x$$

Where: - $$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$5 is initialized with Kaiming uniform distribution ($$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$6). - $$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$7 is initialized to zeros, ensuring $$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$8 at initialization ($$\text{Trigger Repair} \iff (\text{Reward Drop Ratio} \ge \tau_r) \land \left( \text{comm\_effect} < \text{Threshold}_{\text{comm}} \lor \text{Value Sensitivity} < 0.5 \times \text{Baseline} \right)$$9). - $$\text{Recovery}(M) = \frac{M_{\text{repaired}} - M_{\text{degraded}}}{M_{\text{baseline}} - M_{\text{degraded}}}$$0 is the adaptation rank (e.g., $$\text{Recovery}(M) = \frac{M_{\text{repaired}} - M_{\text{degraded}}}{M_{\text{baseline}} - M_{\text{degraded}}}$$1). - $$\text{Recovery}(M) = \frac{M_{\text{repaired}} - M_{\text{degraded}}}{M_{\text{baseline}} - M_{\text{degraded}}}$$2 is the constant scaling factor (e.g., $$\text{Recovery}(M) = \frac{M_{\text{repaired}} - M_{\text{degraded}}}{M_{\text{baseline}} - M_{\text{degraded}}}$$3, yielding scaling $$\text{Recovery}(M) = \frac{M_{\text{repaired}} - M_{\text{degraded}}}{M_{\text{baseline}} - M_{\text{degraded}}}$$4).

7.2 Dynamic Injection & Parameter Freezing

  • Injection (inject_lora_to_actor): Recursively replaces dense feedforward layers in base.mlp.fc1, base.mlp.fc2, and action decoders act.action_out with LoRALinear wrappers while retaining original weights.
  • Selective Training (set_actor_lora_trainable): Freezes all base actor parameters and enables gradients strictly for:
  • LoRA adapter matrices $$\text{Recovery}(M) = \frac{M_{\text{repaired}} - M_{\text{degraded}}}{M_{\text{baseline}} - M_{\text{degraded}}}$$5 and $$\text{Recovery}(M) = \frac{M_{\text{repaired}} - M_{\text{degraded}}}{M_{\text{baseline}} - M_{\text{degraded}}}$$6 across all dense layers.
  • Communication pathway layers (token_embedding, message_head, attention_weight).
  • Centralized Critic parameters (to keep value estimation calibrated).

7.3 Zero-Overhead Inference Merging

When deployed, LoRA weights can be folded directly into the base weights with zero additional latency: $$W_{\text{deployed}} = W_0 + \frac{\alpha}{r} (B \cdot A)$$

8. Summary Comparison of Repair Modes

Target Trainable Parameters Description Primary Use Case
embedding token_embedding Re-learns semantic meaning of discrete tokens; leaves policy trunk and message head frozen. Minimal surgical repair when token vocabulary shifts.
comm token_embedding, message_head, attention_weight Re-learns both what to send, what tokens mean, and peer attention weights. Standard communication failure mode.
lora LoRA adapters on MLP trunk + Action heads + comm pathway Parameter-efficient low-rank adaptation of feature extractors while freezing base weights. Moderate to severe shifts; preserves pre-trained policies without catastrophic forgetting.
full Entire Actor network + attention_weight Full policy retraining on perturbed environment. Complete task and observation breakdown.
noncomm act.action_out only (Control Arm) Trains action decoder without modifying communication layers. Scientific baseline: proves recovery requires fixing communication.
